## 1. 개요

[AI Impact Center](https://github.com/WannaBeSuperteur/ai-impact-center/tree/main) 개발을 위한 베이스라인 코드

### 1-1. 구성 요소

**1. 모델 학습 및 에이전트 파이프라인**

| 파이프라인     | 핵심 모델                              | 주요 플로우                                                                        | 구성 요소                                          | 사용 기술/도구          |
|-----------|------------------------------------|-------------------------------------------------------------------------------|------------------------------------------------|-------------------|
| 딥러닝 모델 학습 | - Vision 이미지 분류 모델<br>- 임의의 딥러닝 모델 | - **(학습)** 데이터 수집 → 전처리 → 모델 학습 → 테스트 → 모델 저장<br>- **(추론)** 모델 로딩 → inference | - 학습 진행 상황 및 테스트 결과 테이블화<br>- 학습 현황 등 그래프 시각화  | `MLflow`          |
| LLM 학습    | Causal LLM (Transformers 라이브러리 기반) | - **(학습)** 모델 다운로드 → 모델 학습 → 모델 저장<br>- **(추론)** 모델 로딩 → 언어 생성 → 필터링 → 최종 답변  | - 정량 평가 (BLEU, ROUGE 등)<br>- LLM-as-a-judge 평가 | `Ollama`          |
| AI 에이전트   | 에이전틱 AI (Causal LLM 기반)            | - 에이전트 기본 플로우 (HuggingFace 모델 기반)<br>- 도구 호출 (Python 함수 실행)                   | -                                              | `smolagents` (예정) |
| 기타 모델 학습  | 텍스트 임베딩 모델 (확률 추론, 유사도 비교)         | -                                                                             | - 확률 추론 (확률 예측)<br>- 유사도 비교                    | -                 |

**2. 모델 연계 파이프라인 (배포 등)**

* 다음 5가지 도구 도입 예상
  * FastAPI, ONNX, MLflow, Ollama, Airflow
* 단, Airflow는 현재가 아닌 차기 버전 도입 예정   
* 프로젝트 조건 고려할 때, 위 기술보다 적절한 기술이 존재하는 경우 해당 기술 사용 가능

### 1-2. 구성 요소 별 사용 기술/도구 및 이유

* 딥러닝 스케줄링 (Airflow) 는 차기 버전에서 고려.

| 구성 요소                         | 사용 기술(도구) 후보                        | 최종 선택 기술(도구) | 최종 선택 이유                                   |
|-------------------------------|-------------------------------------|--------------|--------------------------------------------|
| 딥러닝 모델 학습 진행 상황, 테스트 결과 등 시각화 | **MLflow**<br>KubeFlow<br>SageMaker | **MLflow**   | 오픈소스, Python 통합 쉬움                         |
| 딥러닝 모델 실행 API 서빙              | **FastAPI**<br>Flask<br>Django      | **FastAPI**  | Python 통합 쉬움, 다양한 기능 기본 제공                 |
| 딥러닝 모델 배포/공유/패키징              | **ONNX**                            | **ONNX**     | 다양한 프레임워크 간 모델 교환 포맷으로 대표적인 것은 ONNX가 거의 유일 |
| 거대 언어 모델 (LLM) 서빙             |                                     |              |                                            |
| AI 에이전트 개발                    |                                     |              |                                            |

* 핵심 기준
  * **Python 코드 통합이 쉽고 (추가 구성 요소가 불필요하고), 확장성이 뛰어날수록 좋음** ([AI Impact Center](https://github.com/WannaBeSuperteur/ai-impact-center/tree/main) 개발을 위한 베이스라인 코드이므로)

* 기준 설정
  * 오픈소스 여부 (오픈소스인 것이 좋음)
  * Python 코드 통합 난이도가 쉬울수록 좋음
  * 추가 구성 요소 불필요
  * 기능성 (모델 학습 추적, HPO, 모델 레지스트리 등)
  * 확장성 (다양한 저장소, 백엔드 연동 등)

* 평가 결과
  * 아래 각 기준 별 표의 '최종 점수'에 반영되는 평가 
  * 각 항목 별 4점 만점 (❌ 0점, 보통 2점, 높음/많음 3점, 완벽/✅ 4점)

| 후보               | MLflow                        | KubeFlow                        | SageMaker                             |
|------------------|-------------------------------|---------------------------------|---------------------------------------|
| 오픈소스 여부          | ✅                             | ✅                               | ❌                                     |
| Python 코드 통합 난이도 | **가장 쉬움** (별도 파이프라인 정의 불필요)   | **보통** (컴포넌트, 파이프라인, DAG 정의 필요) | **쉬움** (Amazon AWS 구성 필요)             |
| 추가 구성 요소 불필요     | ✅                             | ❌ (Kubernetes 필요)               | ✅                                     |

| 확장성              | **높음** (다양한 DB, 인프라 연동 가능)    | **높음** (다양한 DB, 인프라 연동 가능)      | **보통** (나머지 2개와 비슷한 수준이지만 AWS 의존성 있음) |

|---------------------------------|--------------------------------------------|---------------------------------|----------------------------|
| 오픈소스 여부                         | ✅                                          | ✅                               | ✅                          |

**3. 딥러닝 모델 배포/공유/패키징 - ONNX**

* **다양한 프레임워크 (TensorFlow, PyTorch 등) 간 모델 교환** 포맷으로 대표적인 것은 **ONNX (Open Neural Network Exchange)** 이고, 그 외에 별다른 후보 없음
* 따라서 딥러닝 모델 배포/공유/패키징 목적으로는 **ONNX 를 사용**
